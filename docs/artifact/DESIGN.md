# Design system — Concept artifact

The visual and content system for this directory's artifact: `index.html` +
`data.json`. `index.html` and `styles.css` are generated files — do not hand-edit;
all content comes from `data.json` and the page files are produced by the
project's generation tooling.

## Design read

*The artifact is the concept's own document, for a cold reader deciding "is this
worth using or learning from?", written in evidence-first language, in a
dark-by-default midnight palette with ice-blue accent and semantic verdict colors.*

## Binding rules

1. **The artifact is the concept's own document.** It carries no assessment-
   methodology branding, no external tool credits, no generator names — the
   concept speaks for itself. The concept's own IDs (`C-###`, `H-###`, `E-###`,
   `S-###`, `D-###`) and paths (including the `.sota/` data directory) are the
   concept's own vocabulary and may appear.
2. **Never hand-edit `index.html` or `styles.css`.** They are generated. All
   content comes from `data.json`.
3. **No CDN, no third-party script, ever.** Fonts are bundled; the chart is
   inline SVG generated by the page's own script from `data.json` series.
   Nothing on the page loads after generation except `data.json` (same
   directory, over HTTP).
4. **Verdicts are never communicated by color alone.** Every chip carries its
   text label; color is redundant reinforcement (WCAG 1.4.1).

## Palette — "Midnight"

Dark by default; the `PAPER/INK` toggle switches to the light palette (persisted
in `localStorage` under `sota-artifact-ink`, respected by `prefers-reduced-motion`).

| Token | Dark (default) | Light (toggle) | Use |
| :--- | :--- | :--- | :--- |
| `--paper` | `#171a20` | `#f6f8fb` | page background |
| `--panel` | `#22272f` | `#e9edf4` | chart, reproduce, limitation panels |
| `--ink` | `#e9edf3` | `#21262f` | body text |
| `--muted` | `#99a2af` | `#5f6676` | captions, meta |
| `--line` | `#343a45` | `#dce1ec` | hairlines, table rules |
| `--accent` | `#7ca7dd` | `#3d5f9e` | links, gauges, chart series, section numerals |
| `--ok` / `--ok-soft` | `#7cc29b` / `#22332a` | `#2f6e4e` / `#dce9e2` | verdict `supported`, scenario `pass`, diffusion `strong` |
| `--warn` / `--warn-soft` | `#d9a05c` / `#382f1e` | `#a16207` / `#f4e8d0` | verdict `partially-supported`, diffusion `partial` |
| `--bad` / `--bad-soft` | `#d97a6e` / `#3b2724` | `#a63a3a` / `#f4dcdc` | verdict `falsified`, dead-ends panel, diffusion `weak` |
| `--idle` | `#8e97a4` | `#7e8295` | verdict `untested`, scenario `unverified`, baseline chart series |

Contrast: body ink on paper exceeds 7:1 in both modes; semantic colors are paired
with their soft backgrounds above 4.5:1, and each is always accompanied by its text.

## Typography

- **Display** (title, question, section titles, pull moments): Source Serif, 600–700.
- **Body**: IBM Plex Sans, 400–600.
- **Mono** (IDs, commands, tables, kickers, captions): IBM Plex Mono, 400–600.
  Mono is restricted to data-adjacent text — design evaluation rejected mono-heavy
  bodies as cold.
- All three families are bundled OFL fonts in `fonts/` (woff2, latin) with their
  license files. No network font fetch.

## Components

Masthead (`CONCEPT C-001` + TRL/SRL/phase/date + toggle) · hero (kicker, serif
title, italic serif question, verdict chip + one-line answer) · claims list with
`E-###` refs · SVG chart (log-x latency curve, crossover marker, legend) ·
reproduce panel · hypothesis blockquote · TRL/SRL gauges · component/scenario/
evidence/repo tables · status and diffusion chips · journey steps · dead-ends
panel (red-tinted) · lessons · limitations grid · audience · letterhead footer
(concept title, repo URL, generated date — nothing else).

## States

- **Verdict chips**: `supported` filled green, `falsified` filled red,
  `partially-supported` amber outline, `untested` dashed neutral. All caps,
  letter-spaced, sans 700.
- **Scenario chips**: `pass` green soft, `unverified` dashed neutral.
- **Diffusion chips**: `strong`/`partial`/`weak` green/amber/red soft.
- **Toggle**: switches `body.ink`; the CSS palette blocks in `:root` (dark) and
  `body.ink` (light) are the only place colors are defined.

## Chart

Inline SVG, no library. `data.json` provides `chart`: title, evidence ref, caption,
`x_ticks` (log scale), `y_ticks`, `ymax`, `crossover`, `series` (one `baseline` in
dashed idle, one `concept` in accent with point dots). The renderer lives in
`index.html`; it uses CSS classes (`chart-grid`, `chart-baseline`, `chart-concept`,
`chart-crossover`…) so the toggle re-colors it automatically. A chart is optional:
if `data.json` has no `chart` block, the section renders without it.

## Accessibility & robustness

- Responsive single column; tables scroll horizontally under 720px.
- `:focus-visible` outlines in accent; semantic landmarks; `lang="en"`;
  heading order 1→2→3.
- `@media print` forces the light palette, hides the toggle, avoids page-breaks
  inside panels.
- No console errors (favicon suppressed with `<link rel="icon" href="data:,">`).
- If `data.json` fails to load, the page shows the load error in plain text —
  the artifact must be served over HTTP (`python3 -m http.server`), which is the
  documented way to view it.

## Layout discipline

Verdict in the first viewport; section headers carry full information; dead-ends
and falsifications are visually loud (red-tinted panel), never buried; claims are
concrete (`E-###`) or deleted. No decoration that could be removed without losing
content — hierarchy comes from type, spacing, and the two accent uses (accent
color, semantic colors).
